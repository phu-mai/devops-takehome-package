Obs-Platform Architecture Proposal

Design principles, architecture map, data flow, and component responsibilities

Design Principles

  • Signal-per-backend separation: Metrics (Mimir), logs (Loki), traces (Tempo).
  • Unified collection: Grafana Alloy is the single OTLP entry point for app telemetry.
  • Multi-tenancy from the ground up: Every hop carries X-Scope-OrgID.
  • Object storage as the durable tier: All backends persist to MinIO (S3).
  • Correlation by convention: Trace IDs flow through logs and metric exemplars.

High-Level Architecture & Data Flow

Component Responsibilities

Alloy (Main)
OTLP receiver, memory limiter, batch processor; routes metrics, logs, and traces to their respective backends with tenant propagation.
Mimir
Monolithic deployment (-target=all,alertmanager,overrides-exporter): distributor, ingester, compactor, store-gateway, query-frontend, ruler, alertmanager, and overrides-exporter.
Loki & Tempo
Dedicated log and trace backends with S3/MinIO storage integration. Tempo also emits span metrics and service graph data directly to Mimir.
Prometheus
Evaluates recording rules across 19 groups plus demo-app alert rules and remote_writes/remote_reads to Mimir.
Grafana
5 provisioned datasources with derived fields, tracesToLogs, tracesToMetrics, serviceMap, and 8 provisioned dashboards.

OPS-ANSWERS

Operational Q&A & mitigation strategies

1) EKS 1.33 → 1.35 zero-downtime upgrade path
Fix deprecated APIs in manifests → upgrade add-ons tracking control plane (vpc-cni, kube-proxy, coredns, CSI drivers) → perform control plane upgrades one minor version at a time → use surge/blue-green Karpenter/nodepools protected by PDBs → re-validate webhooks and storage integrations.
2) Spot reclaim alert storms
Ensure spot nodes are properly labeled (lifecycle: spot); soften or exclude KubeNodeUnreachable alerts for single spot instances. Apply longer evaluation windows (for: 5m-10m) for isolated node unreachability while maintaining fast alerting when multi-AZ failures occur.
3) Cloudflare LCP & HTML caching optimization
Inspect CF-Cache-Status headers; check origin Cache-Control and Set-Cookie headers which bypass edge caching. Implement "Cache Everything" for marketing HTML with appropriate Edge TTLs, and eliminate unnecessary cookies for anonymous visitors to minimize TTFB at the edge.
4) EKS Secrets Management selection
Prefer Kubernetes Secrets + External Secrets Operator backed by AWS Secrets Manager over self-managed Vault: provides native developer experience, granular IAM audit logging, automated rotation, and seamless multi-cluster distribution without the operational overhead of running HA Vault.
